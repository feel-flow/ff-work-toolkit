# ff-work-toolkit

AIと相談しながら、仕事の文章・集計・簡単なアプリを作り、経過を残すためのプラグインです。開発管理やGitHubの操作を覚えなくても、仕事の言葉で依頼できます。

## できること

- 「取引先への案内文を作りたい」から、目的と相手を整理して草案・確認へ進む。
- 「毎月の売上をまとめたい」から、元データと完成条件を決め、件数・合計を照合する。
- 「前の集計はどうなった？」から、記録と成果物を読み、現在地と次の作業を確認する。

最初は短い案内文書から始めます。必要な情報が増えたら文書を分けます。最初から7ファイルや決まったレビュー回数を要求しません。

## 最初の一歩

公開配布先は `feel-flow/ff-work-toolkit` です。Claude Code・Codexのネイティブプラグインとして導入します。スキルファイルを作業先へコピーしません。

Claude Code内で:

```text
/plugin marketplace add feel-flow/ff-work-toolkit
/plugin install ff-work-toolkit@ff-work-toolkit
```

Codexのターミナルで:

```bash
codex plugin marketplace add feel-flow/ff-work-toolkit
codex plugin add ff-work-toolkit@ff-work-toolkit
```

導入・更新後はホストの案内に従い、新しいセッションで始めてください。登録名を変更している場合はそのmarketplace名を使います。

「仕事をAIと進める準備をしたい」と依頼すると、[asdd-init](skills/asdd-init/SKILL.md)で目的・完成条件・保存方法を相談します。その後は [asdd-work](skills/asdd-work/SKILL.md)で依頼・再開・状況確認を扱います。コマンド名を覚える必要はありません。開発者向け版も入れている場合は「ff-work-toolkitで」と指定し、AIは実際に読み込んだプラグインの処理だけを使います。

Node.jsが必要です。GitHubに経過を残す場合は、アカウント・認証済みGitHub CLI・記録先の設定が必要です。成果物の履歴保存や既存ファイルの差分処理にはGitを使います。初回設定は伴走者と行えます。GitHub未接続でもローカルで成果物を作れますが、外部への記録保存は行いません。

## 保存するものを決める

一つの目的を一つのIssueで追い、完成条件、現在地、判断、未決事項、成果物、次の作業を記録します。会話全文や認証情報は保存しません。元データや個人情報を含むファイルは、保存範囲へ勝手に追加しません。

合意した範囲の通常記録は毎回許可を求めず進めます。保存失敗は「未同期」と伝えます。文章を保存しただけで相手に送信したり、アプリを公開したりはしません。

## 収録範囲と開発者向け版への切替

初回版の入口は初期設定と日常作業の2つです。文書検索MCPを同梱し、最小構成の文書も検索対象にします。ACE、自動振り返り、複数AIレビュー、plugin Hook、CIの自動構築は収録しません。既存の組織ルールやCIを削除・緩和しません。

設定は [`.asdd/config.json` の共通契約](docs/configuration.md)を使います。既存設定で未収録機能が有効なら値を消さず、開発者向けのff-dev-toolkitへ切り替える案を提示します。文書・設定・作業ID・履歴を引き継いで差分を確認します。

業務向けの案内・スキルはこのプラグインの正本です。共通処理は配布時に生成同梱し、別の実装として保守しません。ソースcheckoutと配布生成物は異なり、実行には必要な共通処理を含む配布物を使います。
